# volley-bot — требования v1

Телеграм-бот для закрытой группы волейболистов: каждый день сам постит опрос на игру,
следит за плюсами и закрывает опрос, когда состав набран.

Источник требований: обсуждение в самой группе плюс фактический формат опросов, которые
администратор постил руками до появления бота.

## FR — что должно работать

| № | Требование |
|---|---|
| FR-1 | Каждый день в 09:00 (Europe/Sofia) бот постит в группу **неанонимный** опрос «‹дата› Игра 18-00» с вариантами `Плюс` / `Минус` / `Ответ до 16-00` и закрепляет его, снимая свой предыдущий пин |
| FR-2 | 12-й «Плюс» → бот немедленно закрывает опрос (`stopPoll`) и постит «Набор окончен» с составом (с тегами) |
| FR-3 | 8-й «Плюс» → однократный пост «Кворум есть, игра состоится» + имена плюсанувших **без тегов** (чтобы не пинговать людей трижды за день) |
| FR-4 | 17:00: если опрос ещё открыт — закрыть. Плюсов ≥8 → «Играем, N человек» + состав с тегами; <8 → «Не собрались, игры нет» |
| FR-4a | 15:45 (за 15 минут до дедлайна из третьего варианта) бот тегает тех, кто выбрал «Ответ до 16-00», и просит определиться. Простой таймер: пропущенное напоминание не догоняется |
| FR-5 | Команды `/poll` (опрос вне расписания), `/close`, `/status` — только админам группы, список берётся `getChatAdministrators` на каждый вызов |
| FR-6 | `chat_id` бот узнаёт сам при добавлении в группу и переживает миграцию basic group → супергруппу (`migrate_to_chat_id`) |

## SC — чем проверяется

| № | Критерий | Уровень |
|---|---|---|
| SC-1 | Подсчёт по `poll_answer` верен при смене и отзыве голоса: 12-й плюс закрывает; падение с 12 до 11 не вызывает второго закрытия и второго «кворума» | юнит (`tests/test_domain.py`) |
| SC-2 | Рестарт процесса посреди голосования не теряет счёт (состояние в SQLite) | юнит (`tests/test_store.py`) |
| SC-3 | Ровно один опрос в день: процесс лежал в 09:00 и поднялся в 11:00 → опрос создаётся один раз (catch-up до 16:00, позже — пропуск дня) | юнит (`tests/test_startup.py`) |
| SC-4 | **Flow:** бот лишился админки или `stopPoll` упал → в чат идёт внятная ошибка (один раз на опрос), а не тишина; при этом бот **не** говорит «Опрос закрыт», пока опрос открыт | юнит с фейковым ботом (`tests/test_service.py`) |
| SC-5 | Конкурентные апдейты не дублируют действий: два почти одновременных голоса дают один «кворум», один `stopPoll`, один опрос за день | юнит на `asyncio.gather` с задержкой у фейкового Telegram (`tests/test_service.py`) |
| SC-6 | Итог в 17:00 считается по счётчику из ответа `stopPoll`, а не только по своим данным: голоса, потерянные при простое, не превращаются в «игры нет». Счёт сохраняется в базе и переживает повторную попытку публикации | юнит (`tests/test_service.py`) |
| SC-6a | Отрицательный вывод только по авторитетному счёту: «игры сегодня нет» бот говорит, лишь когда счёт дал Telegram; на своих данных — с оговоркой. Положительный вывод из своих данных безопасен: свои плюсы это подмножество настоящих | юнит (`tests/test_texts.py`, `tests/test_service.py`) |
| SC-7 | Живая база доращивает схему сама: новая колонка появляется без потери данных | юнит на базе старой схемы (`tests/test_store.py`) |
| SC-8 | Пропущенный джоб расписания наверстывается в течение часа, а не теряет день | юнит на собранном планировщике (`tests/test_tick.py`) |

## Ограничения Telegram Bot API (проверено по core.telegram.org/bots/api)

1. `poll_answer` приходит боту **только для неанонимных опросов и только для опросов, отправленных самим ботом**. Отсюда `is_anonymous=false` — иначе автозакрытие и теги физически невозможны. Побочный эффект: в группе видно, кто как проголосовал.
2. `stopPoll` работает только для опросов бота — опрос, отправленный человеком, бот закрыть не может.
3. Закрытый опрос **переоткрыть нельзя**: «открыть опрос назад» — только новый опрос.
4. `allows_revoting` для regular-опросов по умолчанию `true` → счётчик плюсов может и падать после объявления кворума. Кворум объявляется один раз за день, повторно не дребезжит.
5. Боту нужны права админа группы: участникам опросы там запрещены, плюс нужен пин.

## Допущения

- 12 = полный состав (две команды по шесть, замен нет), 8 = кворум.
- Игра всегда в 18-00, опрос каждый день без выходных и без отмены.
- Часовой пояс Europe/Sofia. Хостинг — VPS 1, systemd.
- python 3.12 + aiogram 3.30 + APScheduler 3.11, long polling, состояние в SQLite.

## Осознанно не защищено (цена защиты выше цены случая)

- **Крэш ровно между отправкой опроса и записью в базу** — окно порядка миллисекунды.
  Последствие: один бесхозный опрос в группе и второй опрос при следующем тике. Защита
  требует записи «намерения» до отправки, а это новое неполное состояние в базе и риск
  остаться вообще без опроса на день.
- **Повторные попытки объявить кворум**, если чат недоступен: попытка повторяется на 9-м,
  10-м, 11-м плюсе. Максимум четыре, каждая доставляет полезное сообщение.
- **Миграция группы в супергруппу меняет и `message_id`** — открытый в этот момент опрос
  придётся закрыть руками. Случается один раз за жизнь группы.
- **Catch-up при старте выполняется до того, как поллинг вытянет накопившиеся голоса.**
  Бот, поднявшийся после 17:00, закроет опрос по своим данным: решение «играем/нет» спасёт
  счётчик из `stopPoll`, но список имён будет неполным. Синхронный дренаж очереди до тика
  стоит отдельной машинерии ради редкого случая.
- **Потеря базы при живом боте в группе**: `my_chat_member` больше не сработает, привязку
  не восстановить. Лечится удалением и повторным добавлением бота.

## Известные ограничения v1

- **Голоса, поданные пока бот лежал, до него не доходят** — Telegram не даёт API «прочитать
  голоса опроса». Число плюсов в итоге берётся из ответа `stopPoll` и потому верное, но
  перечислить бот может только тех, чьи голоса видел. Обычно это одно и то же.
- **Провал `stopPoll`** (у бота сняли админку) даёт предупреждение в чат и опрос остаётся
  открытым; итог появится, когда админ закроет его руками или права вернут.
- **`/poll` не создаёт второй опрос за день** — даже если сегодняшний уже закрыт: добор в
  v1 не поддержан сознательно.
- **Старт процесса ~12 секунд** на VPS: столько занимает импорт aiogram (pydantic строит
  ~700 моделей). Это не зависание, systemd в это время уже показывает `active`.

## Не в v1

- Добор после закрытия опроса (отвалился игрок → пишут в чат руками, как сейчас).
- Расписание по дням недели и `/skip` (решение: опрос каждый день).
- Статистика посещений, лист ожидания, работа в нескольких группах.
